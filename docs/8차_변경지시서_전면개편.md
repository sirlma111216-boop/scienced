## 2. 이번 개편의 원칙

강의자가 요구한 것 여덟에 아래 다섯을 더 얹는다. 더 얹은 것은 「개선안」으로 표시했다. 강의자가 원하지 않으면 뺀다.

1. **학생이 쓰는 칸은 한 차시에 셋이다.** 도입 하나, 활동 하나(80분 차시는 둘), 정리 하나. 그 이상은 만들지 않는다.
2. **한 번 쓴 것은 다시 쓰지 않는다.** 2차 응답, 재응답, 「생각이 바뀌었으면」 칸은 없다.
3. **읽는 것은 읽기로 끝난다.** 남의 글에 반응·댓글·정렬·묶기를 하지 않는다. 읽고 넘어간다.
4. **개념은 문단으로 설명한다.** 한 줄 구호, 여섯 층, 나열식 핵심 포인트는 없다.
5. **활동은 교사의 결정이다.** 정답이 없는 교실 상황에서 무엇을 할지, 왜 그런지를 쓴다. 활동 자체가 어려우면 안 된다.
6. **모둠은 데이터로 모인다.** 「토의하세요」로 끝내지 않는다. 모둠의 생각이 앱에 남는 형식이 차시마다 하나 있다.
7. **강사는 한 화면에서 수업한다.**
8. **두 과목은 다른 수업이다.**
9. **(개선안) 도입 단계에는 의견 광장을 붙이지 않는다.** 도입은 선택 하나와 그 분포만 본다. 광장은 활동에만 있다. 광장이 차시에 둘 있으면 학생은 어느 것을 읽어야 하는지 모른다.
10. **(개선안) 80분 차시는 개념과 활동을 번갈아 놓는다.** 개념 1부 → 활동 1 → 개념 2부 → 활동 2. 개념 여덟 장을 한 번에 넘기고 활동 둘을 잇달아 하면 앞의 개념을 잊는다.
11. **(개선안) 차시 머리는 셋만 남긴다.** 제목·중심 질문·학습목표 3개. 학생 발화 인용, 첫 문장, 안내, 현장 사례, 흐름 요약, 타임라인, 강사 대본은 지운다.
12. **(개선안) 이론 배경(5차)은 남기되 뒤로 보낸다.** 개념 카드의 탭이 아니라 정리 단계 끝의 「더 읽기」로. 수업 중에는 보이지 않고, 예비교사가 나중에 찾아 읽는다.
13. **(개선안) 50분 판·1시간 판(3차)은 없앤다.** 새 골격은 한 차시가 50분 안에 든다. 판을 나눌 이유가 사라진다. — 14절 질문 1.

### A.2 글에서 빼는 것 (요구 7)

학생이 읽는 모든 문자열에서 아래를 지운다. `verify:wording` 에 규칙을 추가해 **다시 들어오지 못하게 한다.**

| 지운다 | 예 | 검사 |
|---|---|---|
| 설명 없는 비유 | 빈 그릇, 렌즈, 나침반, 뼈대, 지도, 씨앗, 근육, 문을 연다 | 낱말 목록 + 「~는 ~와 같다」 「~처럼」 뒤에 설명 문장이 없으면 실패 |
| 구호 · 한 줄 정리 | 「한 문장으로 말하면」 「기억하세요」 「잊지 마세요」 「핵심은 하나」 「오늘의 한 줄」 | 문구 목록 |
| 다짐 · 약속의 말 | 「~하겠습니다」 「다짐」 「약속」 「내일부터」 「나는 ~하는 교사가 되겠다」 | 문구 목록 |
| 감탄 · 부추김 | 느낌표로 끝나는 문장, 「자, 」로 시작하는 문장, 「멋진」 「놀라운」 「흥미로운」 | 정규식. 게임 화면은 예외 (`// wording-ok: 게임`) |
| 장식 기호 | ★ ✨ 🔥 💡 등 이모지, 「오늘의 문」 「생각 드러내기」 같은 붙인 이름 | 문자 범위 + 이름 목록 |
| 교재 냄새 | 「~에 대해 알아보자」 「~를 살펴보면」 「~라 할 수 있다」 「~의 중요성」 | 문구 목록 |

## 4. 작업 B — 새 차시 골격

### 4.1 교과교수법 — 4단계 (요구 3)

| 단계 | 시간 | 학생이 하는 것 | 화면 |
|---|---|---|---|
| **도입** | 5분 | 장면 하나를 보고 선택 하나 (또는 한 줄) | 자료 1 + 선택형 1. 제출하면 **분포만** 보인다. 광장 없음 |
| **개념** | 15분 | 카드 3~4장을 읽는다. 쓰지 않는다 | 4.4 형식. 강사가 화면을 띄우고 설명한다 |
| **활동** | 25분 | 4.5 의 다섯 단 | 과제 → 쓰기 → 공유 → 모둠 → 게임 |
| **정리** | 5분 | 한 칸 | 4.7 |

합계 50분. 3시간 블록에서는 두 차시 사이에 휴식을 둔다. 50분 두 교시 반에서는 한 교시에 한 차시.

### 4.2 과학교육론 — 두 길이 (요구 2)

**1강**은 교과교수법 1강과 같다 (질문 4). **2~5강은 80분**, **6~12강은 40분**.

**80분 (2~5강)** — 개념이 많고 활동이 둘. 원칙 10 대로 번갈아 놓는다.

| 단계 | 시간 | 내용 |
|---|---|---|
| 도입 | 5 | 4.1 과 같다 |
| 개념 1부 | 15 | 카드 3~4장 |
| 활동 1 | 20 | 다섯 단 — 단, 게임은 짧은 것(6절의 ≤1분 게임) |
| 개념 2부 | 15 | 카드 3~4장 |
| 활동 2 | 20 | 다섯 단 |
| 정리 | 5 | 4.7 |

**40분 (6~12강)** — 개념이 적고 활동이 하나.

| 단계 | 시간 | 내용 |
|---|---|---|
| 도입 | 5 | |
| 개념 | 10 | 카드 2~3장 |
| 활동 | 20 | 다섯 단 |
| 정리 | 5 | |

골격은 `buildStandardSteps` 하나로 그리되 `layout: 'method' | 'edu80' | 'edu40'` 을 받는다. 차시 파일이 단계 배열을 직접 쓰지 않는다.

### 4.3 차시 머리

```ts
Lesson {
  id, order, title
  centralQuestion: string        // 물음표로 끝나는 한 문장. 활동에서 실제로 이 질문에 답하게 된다
  objectives: [string, string, string]   // 「~를 구분한다」 「~를 고른다」 꼴. 「이해한다」 「안다」 금지
  steps: Step[]
  theory?: LessonTheory          // 정리 단계 끝 「더 읽기」에서만 그린다
  published: boolean
}
```

이 셋 말고 머리에 그리는 것은 없다.

### 4.4 개념 카드 (요구 6 · 문제 2)

**여섯 층을 없애고 문단으로 쓴다.** 카드 하나는 화면 한 장이다. 넘길 층이 없다.

```ts
KeyConcept {
  id: string
  name: string                  // 개념 이름. 학술 용어여도 된다
  what: string                  // 문단 1 — 이것이 무엇인가. 3~4문장. 정의를 문장으로 풀어 쓴다
  why: string                   // 문단 2 — 이것이 없으면 교실에서 무엇이 잘못되는가. 2~3문장
  inClass: string               // 문단 3 — 구체적 장면 하나. 학생 발화나 교사 행동 그대로. 3~4문장
  keyPoints: [string, string, string]   // 판단 기준 3줄. 아래 규칙
  confusedWith?: string         // 흔히 섞어 쓰는 것과의 차이. 한두 문장. 필요할 때만
  more?: { title: string; body: string }   // 수업 뒤에 읽는 글 한 편. 접혀 있다
}
```

**`keyPoints` 를 쓰는 규칙** — 이것이 문제 2 의 핵심이다.

- 한 줄은 **완전한 문장**이고 **판단에 쓰는 기준**이다. 「~이 아니라 ~다」 「~이면 ~다」 「~를 보면 ~를 알 수 있다」 꼴을 기본으로 한다.
- 명사 나열 금지. 「구성주의: 능동성, 선지식, 사회적 상호작용」은 기준이 아니다.
- 교재 문장 복사 금지. `verify:content` 가 이미 막고 있고, 이번에 문장 단위 대조를 더한다.
- **읽기 검사** — 강의자가 그 줄만 소리 내어 읽었을 때 「예를 들면」이 자연스럽게 이어져야 한다. 이어지지 않으면 기준이 아니라 요약이다.
- 세 줄이 서로 다른 것을 말해야 한다. 같은 말을 수식어만 바꿔 세 번 쓰지 않는다.

예 (3강 「선개념」):

```
- 학생의 틀린 답은 무지가 아니라 다른 이론에서 나온 답이다. 그 이론이 무엇인지 찾는 것이 먼저다.
- 선개념은 경험에서 왔기 때문에 설명을 한 번 들어서는 바뀌지 않는다. 바뀌려면 그 경험을 다시 겪어야 한다.
- 「무거운 것이 먼저 떨어진다」처럼 일상에서 잘 통하는 생각일수록 오래 남는다. 자주 틀리는 선개념이 아니라 자주 맞는 선개념을 찾아야 한다.
```

**카드 수** — 교과교수법 3~4장, 교육론 80분 각 부 3~4장, 40분 2~3장. 개념이 더 있으면 카드를 늘리지 말고 `more` 나 이론 배경으로 보낸다.

### 4.5 활동 — 다섯 단 (요구 3)

모든 활동은 이 순서다. 순서를 바꾸거나 단을 빼지 않는다.

```
① 과제      상황 + 과제문
② 쓰기      칸 1~2개, 한 번만
③ 공유      의견 광장, 읽기만
④ 모둠      모둠의 생각이 데이터로 모인다 (4.6)
⑤ 게임      발표자 선정 (6절) → 발표
```

```ts
Activity {
  situation: Stimulus           // 교실 장면. 학생 발화 대본·수업 장면·학생 산출물·짧은 기사 중 하나. 200~400자
  task: string                  // 과제문. 명령형 한 문장. 「이 상황에서 교사로서 ___를 정하고 이유를 쓰세요」
  fields: FieldDef[]            // 1~2개. 선택+이유 또는 서술 하나
  share: { prompt: string }     // 광장 안내 한 줄. 「다른 사람은 무엇을 골랐는지 읽어 보세요」 정도
  group: GroupData              // 4.6
  game: GameId                  // 6절
}
```

**활동을 시드에 넣기 전에 통과해야 하는 네 검사.** 각 활동의 코드 주석에 네 답을 적는다. `audit:activity` 가 주석이 있는지 세고, 강의자가 검토 문서에서 읽는다.

| 검사 | 묻는 것 | 실패하면 |
|---|---|---|
| **정답 검사** | 강의자가 이 활동의 정답을 한 문장으로 말할 수 있는가 | 말할 수 있으면 활동이 아니다. 상황을 바꿔 답이 갈리게 한다 |
| **갈림 검사** | 선택형이면, 선택지마다 그것을 고를 만한 이유를 한 문장씩 쓸 수 있는가 | 못 쓰는 선택지는 뺀다. 남는 것이 둘 미만이면 활동을 다시 짠다 |
| **이해 검사** | 상황과 과제문을 한 번 읽은 학생이 30초 안에 무엇을 써야 하는지 아는가 | 상황을 줄이거나 과제문을 다시 쓴다. 개념을 몰라도 「무엇을 쓰라는지」는 알아야 한다 |
| **상황 검사** | 과학교사가 실제 수업·실험·평가·상담에서 맞닥뜨리는 장면인가 | 추상적 물음(「탐구란 무엇인가」)이면 장면으로 바꾼다 |

**활동 소재의 방향** — 상황은 늘 「교사가 무언가를 결정해야 하는 순간」이다. 예: 학생이 틀린 답을 자신 있게 말했을 때 · 실험 결과가 예상과 다르게 나왔을 때 · 두 학생의 설명이 다 그럴듯할 때 · 시간이 10분 남았는데 진도가 안 나갔을 때 · 학부모가 평가 기준을 물을 때 · AI 가 낸 답을 학생이 그대로 냈을 때. 과제는 「무엇을 하겠는가 + 왜」다.

**3강처럼 답이 안 보이는 활동**은 대개 상황이 없이 개념을 묻고 있었다. 「학생의 사고모형을 진단하라」는 검사 셋에 다 걸린다. 「이 학생에게 다음 5분 동안 무엇을 하겠는가」로 바꾸면 통과한다.

### 4.6 모둠 데이터 (요구 4)

모둠 단계는 「토의하세요」가 아니다. **모둠원이 각자 낸 것이 모둠 하나의 값으로 모이고, 그 값이 다른 모둠과 나란히 보인다.** 형식은 다섯 중 하나다.

| 형식 | 학생이 하는 것 | 모둠 값 | 다른 모둠과 나란히 | 맞는 활동 |
|---|---|---|---|---|
| `allocation` 배분 | 요소 4~6개에 100점 | 모둠 평균 | 막대 | 「좋은 수업의 요소」처럼 비중을 정하는 것 (1강) |
| `rank` 순위 | 항목 4~5개 순위 | 순위 합산 → 모둠 순위 | 순위표 | 「먼저 할 것」을 정하는 것 |
| `vote` 투표+이유 | 선택 하나 + 이유 | 모둠 분포 + 대표가 고른 이유 하나 | 분포 | 선택형 활동 |
| `sentence` 합의 문장 | 각자 쓴 것을 모둠에서 읽고 대표가 한 문장 | 문장 하나 | 문장 목록 | 서술형 활동 |
| `sort` 분류 | 카드 6~8장을 두 통에 | 통마다 카드 수 → 갈린 카드 강조 | 갈린 카드 | 「이것은 탐구인가」처럼 경계를 묻는 것 |

- 차시마다 **하나**. 연속 두 차시에 같은 형식을 쓰지 않는다. 배분(%)은 한 학기에 세 번 이하.
- 기존 `GroupBuildConfig`·`GroupPanel`·`groupInputs` 를 이 다섯으로 다시 짠다. 「즉석 모둠(번호 고르기)」은 없앤다 — 모둠은 5절에서 정해져 있다.
- 모둠 값이 모이면 **강사 화면에 모둠별로 나란히** 나온다. 발표는 이 화면을 띄우고 한다.

### 4.7 정리

칸 하나. 문항은 차시마다 다르지만 꼴은 같다 — **「오늘 활동에서 내 결정의 근거가 된 개념은 무엇이었고, 그 개념이 없었다면 무엇을 달리 했겠는가」**. 다짐·소감·한 줄 요약을 묻지 않는다.

정리 화면에는 그 차시 개념 카드의 `keyPoints` 가 **읽기 전용으로 다시** 나온다. 학생은 그것을 보며 쓴다. 제출하면 포트폴리오에 쌓인다. 아래에 「더 읽기」(이론 배경, 접힘).

## 5. 작업 C — 모둠 나누기 (요구 4)

### 5.1 아이스브레이킹 질문으로 나눈다

과학 소재 게임 6종을 없앤다. 대신 **기호를 묻는 질문 하나**로 나눈다.

```ts
FormationQuestion {
  id: string
  question: string              // 「가장 가 보고 싶은 나라는?」
  options: string[]             // 6~8개. 모둠 수 이상
}
```

질문 은행을 `src/content/formation-questions.ts` 에 **20개 이상** 둔다. 예: 가장 가 보고 싶은 나라 · 제일 좋아하는 음료 · 아침형과 저녁형 · 좋아하는 계절 · 라면에 넣는 것 · 여행 가면 먼저 하는 것 · 좋아하는 과일 · 영화관과 집 · 산과 바다 · 강아지와 고양이 · 가장 오래 쓴 앱 · 좋아하는 색. **과학 이야기는 넣지 않는다.**

### 5.2 흐름

```
강사 [모둠 나누기]  →  학생 화면에 질문  →  각자 선택  →  서버 배정  →  강사 미리보기 · 끌어 옮기기  →  확정
```

- **서버 배정**(`/api/groups/assign`, `groups-core.ts`) — 같은 답끼리 모으되, 모둠 크기 ±1 안에서 균형을 맞추고, 6차의 **동석 최소화 비용을 그대로 적용**한다. 답이 몰리면 몰린 답의 사람 일부를 다른 모둠으로 옮긴다. 어느 답이 몰릴지 모르므로 「같은 답끼리」는 우선순위이지 보장이 아니다.
- **모둠 이름 = 답.** 「일본 모둠」 「아이스티 모둠」. 번호 대신 이름으로 부른다. 섞인 모둠은 다수 답의 이름을 쓴다.
- 6차의 결석자 체크·늦게 온 학생 합류·반드시 같이/따로·미리보기의 동석 기록·확정 뒤 학생 화면의 모둠 카드는 **그대로 둔다.** 게임만 바뀐다.
- 질문은 학기 안에 되풀이하지 않는다. 클래스마다 쓴 질문을 기록한다.
- 모둠은 **홀수 차시마다** 새로 나누는 지금 규칙을 유지한다(질문 6 의 답에 따라 바꿀 수 있다).

## 6. 작업 D — 게임 (요구 8)

### 6.1 공통 규칙

- **3분 이내.** 80분 차시의 활동 1 에 붙는 게임은 1분 이내.
- 학생은 **[참가]** 하나, 강사는 **[시작]** 하나. 설명이 필요한 게임은 만들지 않는다. 규칙은 화면 한 줄.
- 결과는 **서버 시드**로 정해지고(기존 `/api/picker/draw`), 결과 화면에 시드와 후보를 남긴다. 조작 의심을 남기지 않는다.
- 발표 횟수가 적은 사람의 가중치(`weightByFewPresentations`)·재추첨·수동 지정·비상 추첨은 유지한다.
- 폰 **세로** 화면에서 된다. 루미 런만 가로.
- 결과 화면에 발표자 닉네임을 **가장 크게.** 발표 모드에서는 그것만 보인다.
- 게임마다 「개인」인지 「모둠 협동」인지 정해져 있다. 모둠 게임은 모둠 단계가 끝난 뒤에만 뜬다.

### 6.2 라이브러리 — 12종

기획서다. **구현 전에 강의자가 이 표를 보고 순서를 고른다 (★).** 강의자가 해 보고 가장 별로인 자리를 루미 런 급으로 바꾼다.

| # | 이름 | 방식 | 인원 | 시간 | 발표자 |
|---|---|---|---|---|---|
| 1 | **폭탄 돌리기** | 서버가 숨긴 시간(15~40초)이 흐른다. 폭탄을 가진 사람은 [넘기기]를 눌러 무작위 다른 사람에게 보낸다. 시간이 끝났을 때 든 사람 | 개인 | 1분 | 폭탄 든 사람 |
| 2 | **숫자 가까이** | 각자 1~100 중 하나를 고른다. 서버가 숫자를 뽑는다. 가장 가까운 사람 | 개인 | 30초 | 가장 가까운 사람(동점 공동) |
| 3 | **문 세 개** | 문 셋 중 하나를 고른다. 서버가 한 문을 연다 — 그 문을 고른 사람은 통과. 남은 사람으로 다시. 마지막까지 남은 한 사람 | 개인 | 2분 | 끝까지 안 뽑힌 사람 |

| 5 | **늦게 눌러라** | 10초 카운트다운. 가장 늦게 누른 사람이 발표. 0 이 지난 뒤 누르면 탈락. 눈치 게임 | 개인 | 30초 | 유효한 마지막 사람 |
| 6 | **가위바위보 토너먼트** | 서버가 짝을 짓는다. 동시에 낸다. 진 사람이 탈락. 마지막 승자 | 개인 | 2분 | 우승자 (또는 첫 탈락자 — 차시별 선택) |
| 7 | **동시에 눌러라** | 모둠원 전원이 [지금]을 누른다. 누른 시각의 편차가 **가장 작은** 모둠 | 모둠 협동 | 30초 | 그 모둠의 대표 |
| 8 | **비밀 합** | 모둠원이 각자 1~5 를 고른다(말하지 않고). 합이 서버가 정한 목표에 가장 가까운 모둠 | 모둠 협동 | 30초 | 그 모둠의 대표 |
| 9 | **릴레이 단어** | 모둠원이 순서대로 한 글자씩 넣어 서버가 준 여섯 글자 낱말을 완성한다. 가장 빠른 모둠 | 모둠 협동 | 1분 | 그 모둠의 대표 |
| 10 | **빙고** | 아이스브레이킹 답 9개로 3×3 판. 서버가 항목을 하나씩 뽑는다. 첫 빙고 | 개인 | 2분 | 첫 빙고 |
| 11 | **추정** | 「이 강의실에서 커피를 고른 사람은 몇 명?」처럼 그날 모둠 질문의 답 수를 맞힌다. 가장 가까운 사람 | 개인 | 30초 | 가장 가까운 사람 |

**공정성 표시** — 5·12 처럼 반응 속도에 기대는 것은 기기·회선에 따라 달라진다. 결과 화면에 「반응 속도 게임입니다」를 적고, 한 학기에 두 번 이하로 쓴다.

- `PickerVisual.tsx`(723줄)를 게임별 파일로 나눈다. `src/components/games/<mode>.tsx`. 공통 틀(참가·시작·결과·재추첨)은 `GameShell.tsx` 하나.
- 실시간 동기화는 기존 `sessions/{lessonId}.ladder` 문서를 `sessions/{lessonId}.game` 으로 이름을 바꿔 쓴다. 게임마다 상태 모양이 다르므로 `state: unknown` 에 게임별 파서.
- 반응 시각(5·7·12)은 **서버 시각**을 쓴다. 클라이언트 시각은 믿지 않는다. 참가 시 서버가 오프셋을 준다.
- `verify:games` — 라이브러리 13종 등록 · 차시마다 게임 하나(80분은 둘) · 연속 차시 중복 없음 · 모둠 게임은 모둠 단계 뒤 · 서버 시드.

## 7. 작업 E — 강사 수업 화면 (요구 5 · 문제 5)

### 7.1 한 화면

경로 하나: **`/teach/:classId/:lessonId`**. 강사가 차시를 열면 여기다. 다른 강사 화면으로 넘어갈 일이 수업 중에는 없다.

```
┌──────────────────────────────────────────────────────────────┐
│ 2강 과학지식은…  │ 도입 ● 개념 ○ 활동 ○ 정리 ○ │ 발표 모드 │ 실명 가리기 │ 명단 12/28 │  ← 고정
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  ▌도입                                          [단계 열기]  │
│   자료: 발자국 사진                        [자료 공개] [되돌리기]│
│   선택: 이것은 무엇인가                   응답 12/28 ▸ 분포   │
│                                                              │
│  ▌개념                                          [단계 열기]  │
│   카드 1 ─ 관찰과 추론 ……… (학생이 보는 그대로)              │
│   카드 2 …                                                   │
│                                                              │
│  ▌활동                                          [단계 열기]  │
│   ① 상황 ……                                                  │
│   ② 쓰기                                  응답 9/28 ▸ 목록   │
│   ③ 공유 (광장)                           올라온 글 9 ▸      │
│   ④ 모둠 — 합의 문장                     [모둠 나누기] 모둠별 ▸│
│   ⑤ 게임 — 폭탄 돌리기                   [시작]  참가 20/28  │
│                                                              │
│  ▌정리                                          [단계 열기]  │
│   한 칸                                   응답 0/28 ▸        │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

- **본문은 학생 화면과 같은 부품이 그린다.** `Lesson.tsx` 의 블록 부품에 `teacher` 속성을 주면 그 블록 옆에 조작부가 붙는다. 강사용 화면을 따로 만들지 않는다 — 7차의 근본 원인(따로 만들어서 어긋난다)을 이번에 끝낸다.
- **조작부는 블록 옆에 인라인.** 7차 Q.2 등록표(`console-registry.ts`)를 그대로 쓰되, 덮개 화면이 아니라 그 자리에 그린다.
- **위에서 아래로 한 흐름.** 단계 알약을 눌러도 화면이 바뀌지 않고 그 위치로 스크롤한다. 강사는 진도를 따라 내려간다.
- **응답은 접혀 있다.** 「응답 12/28 ▸」를 누르면 그 아래에 분포나 목록이 펼쳐진다. 학생 하나를 누르면 그 학생의 이 차시 응답 셋이 나란히.
- **[단계 열기]** 는 그 단계의 모든 칸을 학생에게 연다. 칸 하나씩 열지 않는다. 자료 공개만 따로다.
- **명단 12/28** 을 누르면 오른쪽 서랍. 참석·제출·미제출. 발표 모드에서는 숫자만.
- **발표 모드**는 이 화면을 프로젝터용으로 바꾼다 — 조작부와 응답 수를 숨기고, 글자를 키우고, 실명을 닉네임으로. 별도 경로가 아니라 같은 화면의 상태다. 7차 S 의 규칙(rosterName 안 읽기, CSV 막기)은 유지.

### 7.2 없애는 화면

| 없앤다 | 대신 |
|---|---|
| `/instructor/lesson/:id/live` 진행 콘솔 | `/teach/…` |
| 학생 화면의 강사 전용 요소 (PlanPreviewBar · TierBadge · 강사 이동 배너) | `/teach/…`. 학생 경로 `/lesson/:id` 는 학생만 쓴다 |
| `/instructor/lessons` (공개 토글) | 클래스 안 차시 목록으로. 클래스를 고르면 차시 목록이 나오고, 행마다 공개 토글과 [수업 열기] |
| `/instructor` 대시보드의 통계 | 클래스 목록으로 바로 |
| `/instructor/analytics` · `/instructor/ai-review` | 질문 7. 안 쓰면 숨긴다 |

강사 홈은 **클래스 목록 → 차시 목록 → 수업 화면** 세 단계다. 학생 관리는 클래스 목록에서 들어간다.

### 7.3 강사가 수업 중에 누르는 것

여섯 가지뿐이다. 이 밖의 단추가 수업 화면에 있으면 `verify:teach` 가 실패한다.

`단계 열기` · `자료 공개` · `모둠 나누기` · `게임 시작` · `발표 모드` · `응답 펼치기`

## 8. 작업 F — 두 과목 분리 (요구 2 · 6)

### 8.1 구조

```
src/content/courses/
  method/            교과교수법 18차시
    lesson01.ts … lesson18.ts
  edu/               과학교육론 12차시
    lesson01.ts … lesson12.ts
  index.ts           COURSES = { method, edu }
```

```
classes/{classId}
  courseId: 'method' | 'edu'
  courseTitle: string          // 그대로. 표시 이름
```

- 클래스는 과목 하나에 속한다. 학생 홈·포트폴리오·개념 지도는 그 과목의 차시만 보인다.
- 응답·광장·모둠 데이터는 `classes/{cid}/…` 아래라 그대로다. `lessonId` 두 자리도 그대로 — 클래스가 과목을 알기 때문에 충돌하지 않는다.
- 검증기는 `COURSES` 를 돌며 과목마다 검사한다. `LESSON_IDS` 18 고정을 없앤다.
- 게임·모둠 질문·이론 배경도 과목별로 등록한다.

### 8.2 과학교육론 12강 주제 초안

교과교수법에서 「왜 그런가(이론·연구)」 쪽을 가져오고, 「어떻게 하는가(설계·실행)」 쪽은 교과교수법에 남긴다. **강의자가 확인한다 (질문 3).**

| 교육론 | 길이 | 주제 | 교수법의 어디에서 |
|---|---|---|---|
| 1 | — | 좋은 과학 수업은 무엇을 남기는가 | 1 그대로 |
| 2 | 80 | 과학지식의 본성 — 관찰·추론·잠정성·과학 공동체 | 2 |
| 3 | 80 | 학습이론 — 선개념·구성주의·비고츠키·오수벨 | 3 + 4 |
| 4 | 80 | 개념변화 — 인지 갈등·개념생태·POE | 5 |
| 5 | 80 | 과학과 교육과정 — 2022 개정의 구조·성취기준·역량 | 6 + 7 |
| 6 | 40 | 탐구의 본성과 과학적 실행 | 8 + 9 |
| 7 | 40 | 교수·학습 모형의 원리 | 10 |
| 8 | 40 | 설명·비유·모형·표상 | 11 |
| 9 | 40 | 질문·논증·CER | 12 |
| 10 | 40 | SSI 와 과학적 소양 | 13 |
| 11 | 40 | 협동학습과 포용 | 14 |
| 12 | 40 | 과학 평가의 원리 — 형성·수행 | 15 + 16 |

디지털·AI(17)와 PCK·마이크로티칭(18)은 교수법에만 둔다.

### 8.3 다르게 보이게 하는 규칙 (요구 6)

두 과목을 같이 듣는 학생이 **다른 수업**을 듣는다고 느껴야 한다.

- **자료·상황·활동을 공유하지 않는다.** 같은 개념이어도 도입 장면, 활동 상황, 모둠 데이터 형식이 다르다. `verify:course` 가 두 과목의 `Stimulus.body`·`task`·`situation` 을 대조해 문장 단위 중복이 있으면 실패한다.
- **개념 카드는 `what`·`keyPoints` 까지 달라야 한다.** 교육론은 이론·연구·인명이 `what` 안에 들어가고, 교수법은 교실 장면이 `what` 안에 들어간다. `inClass` 는 두 과목이 다른 장면을 쓴다.
- **게임과 모둠 질문이 겹치지 않는다.** 6.3 배치표와 5.1 질문 은행에서 두 과목이 같은 주에 같은 것을 쓰지 않도록 시드가 어긋나게 배치한다.
- **1강만 같다** (질문 4).

## 9. 글쓰기 규칙 — 새로 쓰는 모든 문장에

- 학생이 읽는 글은 **「~다」 「~하세요」** 두 어미만 쓴다. 「~해 봅시다」 「~해 볼까요」 없다.
- 한 문단은 4문장 이하. 한 문장은 60자 이하.
- 개념을 설명할 때 **예를 먼저 들지 않는다.** 정의 → 예. 예가 먼저 오면 학생은 예를 개념으로 기억한다.
- 학술 용어는 처음 나올 때 한 번 풀어 준다(기준 문서 D4 그대로). 두 번째부터는 용어만.
- 상황(대본·산출물)은 기준 문서 A3 의 「꼬리표␣␣내용」 꼴 그대로.
- 지어낸 자료는 `label: '수업용으로 만든 가상 자료'` 그대로 (A2).
- 교재의 심화 읽기에서 복사하지 않는다 (F5 그대로).

## 10. 확인 방식 — 강의자를 소모시키지 않는 법 (문제 4)

이번 작업에서 강의자가 확인하는 것은 **딱 두 종류**다. 그 밖에는 Claude Code 가 스스로 정하고 검사한다.

### 10.1 내용 — 검토 문서 한 장

차시 하나를 코드로 쓰기 **전에** `docs/검토/<과목>-<nn>.md` 를 만든다. 강의자는 이것만 읽는다. 10분 안에 읽히지 않으면 너무 긴 것이다.

```
# 교과교수법 7강 — 성취기준을 한 차시 수업으로 바꾸기

중심 질문   …
학습목표    1 … 2 … 3 …

## 도입 (5)
장면   [대본 그대로]
질문   … / 선택지 …

## 개념 (15)
### 카드 1 ─ 이름
무엇      [문단]
왜        [문단]
교실에서  [문단]
기준      1 … 2 … 3 …
### 카드 2 …

## 활동 (25)
상황   [대본·산출물 그대로]
과제   …
칸     …
모둠   형식: vote — …
게임   폭탄 돌리기
검사   정답: … / 갈림: … / 이해: … / 상황: …

## 정리 (5)
문항   …

## 이렇게 정했다
- … (판단이 갈렸던 것과 이유)
```

강의자는 문서에 **직접 고쳐 써서** 돌려주거나 「그대로」라고 한다. 고친 문서가 곧 시드다. Claude Code 는 그것을 코드로 옮기고 `audit` 이 문서와 코드가 같은지 센다.

### 10.2 기능 — 본보기 한 편

기능은 **교과교수법 1강**을 새 틀로 완성해 한 번만 확인받는다. 강사 수업 화면·게임·모둠까지 1강에서 다 돌아가면, 나머지는 같은 부품이므로 강의자가 다시 확인하지 않는다. 확인은 배포된 주소에서 강의자가 학생 계정 하나와 강사 계정으로 **한 차시를 끝까지** 해 보는 것이다. 단추 하나씩 확인하지 않는다.

### 10.3 Claude Code 가 하지 않는 것

- 「이 화면을 확인해 주세요」 「이 단추가 되는지 봐 주세요」 — 하지 않는다. `scripts/test-*.mjs` 로 에뮬레이터에서 스스로 확인한다.
- 판단이 갈리는 것을 그때그때 묻지 않는다. 정하고 「이렇게 정했다」에 적는다.
- 한 번에 두 가지 이상을 묻지 않는다.

```
F  교과교수법 나머지
   F-1  2강 검토 문서 → 코드 (1·2강은 이미 수업에 썼으므로 내용은 옮기기만)
   F-2  3~6강 검토 문서 4장 한꺼번에                                ★
   F-3  7~18강 검토 문서, 세 장씩                                   ★ ×4
        (각 묶음: 문서 → 강의자 고침 → 코드 → audit:draft → 공개)
G  과학교육론
   G-1  8.2 주제표 확정 (질문 3 에서 답을 받았으면 생략)
   G-2  2강 검토 문서 (80분 본보기)                                  ★
   G-3  3~5강 세 장                                                ★
   G-4  6강 검토 문서 (40분 본보기)                                  ★
   G-5  7~12강 세 장씩                                             ★ ×2
H  마무리
   H-1  README · CLAUDE.md · DESIGN.md 를 현재 구조로 (README 의 검증기 13종·MustSay 같은 옛 서술 제거)
   H-2  부록의 보안 문제 둘
   H-3  배포 번들에서 새 문장 grep → 완료
```

**이번 학기 진도와 맞추기** — 오늘 기준으로 교과교수법은 4강까지 끝났다. A 를 먼저 배포하면 5·6강은 옛 내용이지만 재응답·반응이 빠진 채로 수업할 수 있다. 7강부터 새 틀이 필요하므로 **E → F-3 의 7강**을 다른 것보다 먼저 당길 수 있다. 질문 6.

## 13. 완료 확인

1. 학생은 한 차시에 세 번(80분은 네 번)만 쓴다. 다시 쓰는 칸이 어디에도 없다.
2. 의견 광장에 반응·댓글·정렬·묶기가 없다. 읽고 넘어간다.
3. 개념 카드는 넘길 층이 없다. 문단 셋과 기준 3줄이 한 화면에 있다.
4. 모든 활동의 코드 주석에 네 검사의 답이 있고, 검토 문서와 같다.
5. 모둠은 아이스브레이킹 답으로 나뉘고 답이 모둠 이름이다. 동석 최소화는 그대로 돈다.
6. 모둠의 생각이 차시마다 데이터 하나로 모이고, 강사 화면에 모둠별로 나란히 나온다.
7. 강사는 `/teach/…` 한 화면에서 수업을 시작해 끝낸다. 다른 강사 화면으로 넘어가지 않는다.
8. 수업 화면의 단추는 여섯 종류뿐이다.
9. 과학교육론 클래스와 교과교수법 클래스를 만들면 차시 수·길이·자료·활동이 다르다. 두 과목을 같이 듣는 학생 계정으로 들어가면 같은 문장을 두 번 보지 않는다.
10. 게임 라이브러리 13종이 등록되어 있고, 강의자가 배치를 바꿀 수 있다.
11. A.2 의 낱말·문구가 학생 화면 어디에도 없다.
12. `verify` 전부 · `tsc` · `lint` · `build` 통과. 배포 번들에 검토 문서의 문장이 있다.

## 14. 시작 전에 물어볼 것

1. **50분 판·1시간 판(3차의 tier)을 없애도 되는가?** 새 골격은 한 차시가 50분 안에 든다. 없애면 판 미리보기·배지·「수업 후 이어서」·`verify:tiers` 가 함께 사라진다. 남기면 강사 화면이 단순해지지 않는다.
2. **루미 런**은 지금 교과교수법 3·4강에 붙어 있다. 그대로 둘지, 다른 차시로 옮길지, 일단 빼 두었다가 강의자가 「가장 별로인 게임」 자리에 넣을지?
3. **8.2 의 과학교육론 12강 주제 초안**을 그대로 쓸지, 고칠 곳이 있는지?
4. **과학교육론 1강**은 교과교수법 1강과 같은 내용으로 두는가? 두 과목을 같이 듣는 학생은 첫 주에 같은 수업을 두 번 듣게 된다.
5. **이론 배경(5차)**을 정리 단계 끝 「더 읽기」로 남길지, 아예 뺄지? (권장: 남긴다. 예비교사가 용어를 찾는 자리다.)
6. **작업 순서** — A 를 먼저 배포하고 7강을 새 틀로 당기는 것(12절 끝)이 이번 학기 진도에 맞는가? 아니면 처음부터 순서대로?
7. **학습 분석·AI 검토·마이크로티칭·개념 지도·교육과정 맵** 화면 중 이번 학기에 쓰는 것은? 안 쓰는 것은 숨긴다.
8. **모둠을 새로 나누는 주기** — 지금은 홀수 차시마다. 교육론 12강에서는 어떻게 할까? (권장: 교육론도 홀수 차시.)

## 부록 — 함께 고칠 보안 문제 둘

이번 개편과 별개로 지금 저장소에 있는 것이다. H-2 에서 고친다.

**① 미공개 차시 내용이 모든 학생의 브라우저로 내려간다.** 18차시 콘텐츠가 앱 번들 하나에 다 들어 있다. `published: false` 인 차시도 개발자 도구로 읽을 수 있다. `App.tsx` 의 「미공개 차시 내용은 전송하지 않는다」와 어긋난다. 고치는 법: 차시 파일을 `import()` 로 나누어 공개된 차시만 불러오거나, 공개 여부를 서버가 확인한 뒤 내려보낸다. 두 과목으로 나누면 번들도 나뉘므로 이때 같이 한다.

**② 루미 런의 발표 등수가 번들에 있다.** `games.ts` 의 `lumi.ranks` 가 번들에 그대로 있어 학생이 미리 알 수 있다. 4강은 1·3등이라 알면 일부러 늦게 들어올 수 있다. 고치는 법: `ranks` 를 `functions/` 쪽으로 옮기고 티켓 발급 때 강사 요청에만 붙인다. 게임 라이브러리로 옮길 때 같이 한다.
