# 강의 일괄 수정 기준 — 1·2강에 맞춰 3~18강을 고치는 법

강의자가 **「3, 4강을 지난 강의들처럼 일괄로 수정해」** 라고 하면 이 문서대로 한다.
다시 물어보지 않는다. 여기 적힌 것이 그 지시의 내용이다.

기준은 두 곳에 있다.

| | 무엇 | 누가 읽나 |
|---|---|---|
| `docs/강의-일괄-수정-기준.md` | 무엇을 왜 그렇게 하는가 | 사람 |
| `scripts/audit-lesson.mjs` | 그것이 됐는지 센다 | 기계 |

**둘이 어긋나면 스크립트가 맞다.** 문서를 고친다. 항목 번호(A1·B1·D4…)는 양쪽이 같다.

```bash
npm run audit:lesson -- 03 04
```

---

## 지시를 받으면 하는 일 (순서)

1. **`npm run audit:lesson -- <차시>`** 로 빈 곳을 뽑는다. 눈으로 훑지 않는다.
2. 아래 항목 순서대로 채운다. **A(자료) → B(안내) → C(그림) → D(개념 카드) → E(칸·말)**
   자료를 먼저 만들어야 안내 문구가 그 자료를 가리킬 수 있다. 순서를 바꾸면 두 번 쓴다.
3. `npm run audit:lesson -- <차시>` 가 **빈 곳 0** 이 될 때까지 돌린다.
4. `src/content/types.ts` 의 `INITIALLY_OPEN` 에 그 차시를 넣고 `published: true` 로 바꾼다.
   → 이 순간부터 `verify:stimulus`·`verify:lessons`·`verify:figures` 가 그 차시에 **엄격 모드**로 걸린다.
5. `npm run verify && npm run typecheck && npm run lint`
6. 커밋 → 배포 → **배포된 번들에서 새 문장 하나를 grep 으로 확인**한 뒤에 완료라고 말한다.

한 차시에 드는 분량은 대략 이렇다. 미리 알고 시작한다.

- 자료 4벌 (기사·대본·학생 산출물·표 중에서) — 각 300~600자
- 개념 카드 4장 × (`mustKnow` 5줄 + `deepDive` 3편) — 이것이 가장 크다
- `doNow` 5줄, 그림 명세 0~1개

## A · 자료 — 학생이 붙들 실물

### A1 자료 실물

**규칙** 학생이 밖의 무언가를 놓고 판단하는 단계에는 읽을 것·볼 것이 실제로 있어야 한다.
`format: 'note'` 는 4차 지시서 이전의 상황 소개 글이다. **전부 실물로 바꾼다.**

3~18강은 지금 `phenomenon` 하나(= `note` 한 장)뿐이고 나머지 세 단계는 비어 있다.
2강처럼 네 자리를 채운다.

| 단계 | 2강이 놓은 것 | 형식 |
|---|---|---|
| `step-open` | 발자국 사진 | `image` |
| `step-concepts` | — (개념 카드가 자료다) | 없음 |
| `step-module` | 기사 한 편 + 증거 카드 두 장 | `article` · `card` |
| `step-formative` | 학생 보고서 한 편 | `studentWork` |
| `step-wrapup` | 학생 발화 대본 | `dialogue` |

`_common.ts` 의 `openStimuli` · `moduleStimuli` · `formativeStimuli` · `wrapupStimuli` 에 넣는다.
`openStimuli` 를 주면 `phenomenon` 은 쓰이지 않으므로 **`phenomenon` 을 지운다.**

**왜** 「뉴스에 실린 주장 하나를 받습니다」라고 적어 놓고 받을 것이 없으면 그것은 활동이 아니다.
지시서가 활동을 「상호작용 형태」로만 지정해 와서, 슬라이더는 만들어졌는데 읽을 기사는
아무도 만들지 않은 자리가 18차시에 널려 있었다.

**면제** 학생 자신의 경험·판단을 꺼내는 단계는 자료가 없는 것이 맞다.
1강의 `step-recall`·`step-auction`·`step-wrapup` 이 그렇다.
면제는 `scripts/audit-lesson.mjs` 의 `자료_면제` 에 **이유와 함께** 적는다. 조용히 넘기지 않는다.

### A2 자료 꼬리표

**규칙** 지어낸 자료에는 `label: '수업용으로 만든 가상 자료'`, 실제 출처가 있으면 `source` 를 붙인다.
`note` 와 `standard`(성취기준)는 면제.

**왜** 학생이 가상 기사를 실제 보도로 알고 나가면, 그 수업이 가르친 것은 잘못된 사실이다.

### A3 줄머리 구분

**규칙** `dialogue` 와 `studentWork` 의 본문은 **「꼬리표␣␣내용」** 모양으로 쓴다.
공백 **두 칸 이상**이 꼬리표와 본문을 가른다. 꼬리표는 15자 이내.

```
교사    자, 지난 시간에 했던 실험을 떠올려 봅시다.
민서    선생님, 그런데 왜 하얀 게 위로 올라갔어요?
        (컵을 가리키며)
제목    식물의 잎 개수와 성장 속도
방법    화분 두 개에 같은 양의 물을 주고 2주간 관찰했다.
```

- 이어지는 줄은 **공백으로 시작**한다 → 앞 줄에 붙는다
- `(1분)` 처럼 괄호만 있는 줄은 지문으로 그려진다
- 꼬리표도 들여쓰기도 없는 줄이 섞이면 화면이 들쭉날쭉해진다 — 감사기가 잡는다

**왜** 「제목 식물의 잎의 개수와…」가 한 덩어리로 읽히면 학생이 「제목」이 꼬리표인지
「제목 식물」이라는 말인지 모른다. 화면은 꼬리표를 따로 그리는데 그러려면 이 모양이어야 한다.
판정은 `src/lib/body-text.ts` 의 `parseBody` 가 하고, **화면과 검사가 같은 함수를 쓴다.**

### A4 자료 연결

**규칙** 칸의 `label` 이나 `help` 가 「이 기사가」 「아래 표를 보고」처럼 무언가를 가리키면
`requiresStimulus: ['자료id']` 로 어느 자료인지 못 박는다. 그 id 는 **같은 단계에** 있어야 한다.

**왜** 가리키는 말만 있고 가리킬 것이 없으면 학생은 화면을 위아래로 뒤진다.
연결해 두면 화면이 그 자료를 칸 옆에 붙여 그린다.

## B · 안내 — 지금 무엇을 하는가

### B1 지금 할 일 (`doNow`)

**규칙** 칸이 있거나 개념 카드가 있는 단계마다 **명령형 한 문장**.
두 줄 금지. 물음표로 끝내지 않는다. 학생이 **지금 손으로 할 행동**만 적는다.

2강:

```ts
doNow: {
  open: '아래 발자국 사진을 보고, 본 것과 그것이 무엇이라고 생각하는지를 다른 칸에 각각 적으세요.',
  concepts: '카드 네 장을 순서대로 열고, 카드마다 「잠깐 확인」에 답하세요.',
  module: '아래 기사를 읽고, 기사가 실제로 주장하는 바를 한 문장으로 적으세요.',
  formative: '아래 학생 보고서를 읽고, 교사로서 가장 먼저 짚을 것을 고른 뒤 이유를 적으세요.',
  wrapup: '아래 학생의 말에 교사로서 할 답을 한 문장으로 적으세요.',
}
```

**하지 않는 것** 강사가 할 일을 학생 안내에 넣지 않는다(4차 H.2).
「분포를 열어 보여 줍니다」는 학생이 할 일이 아니다.

### B2 여는 조건 (`gate`)

**규칙** 「토론 뒤」 「새 증거 뒤」 「제출 후」로 시작하는 칸에는 `gate` 와 `lockedMessage` 를 붙인다.
잠긴 칸은 입력 요소를 **아예 그리지 않는다** — 회색 카드와 여는 조건만 남는다.

형성평가의 2차 두 칸은 `_common.ts` 가 이미 붙여 준다. **차시별로 새로 넣을 일은 대개 없다.**
모듈 단계에 「증거를 공개한 뒤에 쓰는 칸」을 새로 만들 때만 직접 붙인다.

```ts
gate: { type: 'afterReveal', of: 'evidence-card-2', lockedMessage: '새 증거 카드가 공개되면 열립니다.' }
```

**왜** 조건 없이 다 열어 두면 학생 화면에 같은 질문이 두 번 있는 것으로 보인다. 18차시가 모두 그랬다.

## C · 그림

### C1 그림 명세

**규칙** `format: 'image'` 인 자료에는 `imageSpec` 이 통째로 있어야 한다.
`purpose` · `mustShow` · `mustNotShow` · `labels` · `genPrompt` · `altText` · `fallback` · `license`.

> **★ 그림은 내가 그리지 않는다.**
> 도형으로 흉내 낸 그림은 생성 도구의 결과보다 못하다.
> **내 몫은 `genPrompt` 까지다.** 강의자가 그것으로 파일을 만들어 `public/figures/` 에 넣고
> `src` 를 채운다. 파일이 없는 동안 화면은 `altText` 와 `fallback` 을 대신 그린다.

**그림 안에 한국어 글자를 넣지 않는다.** 생성 도구가 한국어를 제대로 못 쓰고,
박힌 글자는 확대·화면 낭독·번역에서 빠진다. 라벨은 앱이 위에 겹쳐 그린다(`labels` 의 `x`·`y`).
그래서 `mustNotShow` 에 「그림 안의 어떤 설명 문구도」가 반드시 들어간다.

`altText` 는 **그림을 보지 않고도 같은 판단을 할 수 있을 만큼** 쓴다. 80자 미만이면 감사기가 막는다.

**파일을 갈아 끼울 때** `src` 뒤 `?v=` 숫자를 올린다.
파일이 없던 동안 그 주소로 `index.html` 이 내려가 4시간짜리 캐시로 굳은 적이 있다(Cloudflare 는
없는 경로에 SPA 를 돌려준다). 주소를 바꿔야 그 캐시를 비껴간다.

## D · 개념 카드

여섯 층(`plainOneLiner` … `applyQuestion`)은 3~18강도 이미 갖추고 있다.
**빠진 것은 아래 넷이다.** 분량으로 보면 일괄 수정의 대부분이 여기다.

### D1 꼭 알아야 할 것 (`mustKnow`)

**규칙** 카드마다 **3줄 이상**(2강은 5~6줄). 한 줄에 한 가지.
외울 문장이 아니라 **판단에 쓰는 기준**으로 쓴다. 카드의 어느 층을 보고 있든 늘 보인다.

**왜** 강의자가 강조해서 읽을 대목이자 학생이 시험 공부에 쓸 알맹이다.
층을 넘겨야 나오면 아무도 못 본다.

### D2 더 읽기 (`deepDive`)

**규칙** 카드마다 `{ title, body }` **1편 이상**(2강은 3편). 강의에서 말로 하는 것을 글로 남긴다.
여섯 층은 강의 중에 넘기는 화면이고, 이것은 **수업 뒤에 혼자 읽는 본문**이다.

2강이 쓴 세 편의 꼴이 좋은 본보기다 — ① 왜 이 구분이 필요한가 ② 흔한 오해 하나 ③ 교실에서 바로 쓰는 장치.

### D3 강조 표시

**규칙** `mustKnow` 와 `deepDive` 본문에서 **강사가 소리 내어 읽을 대목**을 `**볼드**` 로 짚는다.
카드마다 최소 하나. 화면이 `withEmphasis` 로 굵게 그린다.

**왜** 강의자가 화면을 띄워 놓고 어디를 짚어야 할지 매번 찾지 않게 한다.

### D4 줄임말 풀이

**규칙** 학생이 읽는 글에 나온 줄임말은 **한 번은 풀어 준다.** 집 문법은 이렇다.

```
'**CER** — 주장(Claim) · 증거(Evidence) · 추론(Reasoning). 논증이 성립하려면 셋이 다 있어야 하고…'
'**PISA** — OECD 가 3년마다 만 15세 학생을 대상으로 치르는 국제 학업성취도 평가다.'
```

`**줄임말**` 바로 뒤에 줄표(`—`). 감사기가 이 모양을 찾는다.

대문자 두 자 이상을 모두 줄임말로 보므로 **로마 숫자 같은 것도 걸린다.**
그때 할 일은 둘 중 하나다 — 집 문법으로 풀어 주거나, **이유를 달고** `설명_면제` 에 넣거나.
(지금 들어 있는 것: `AI` `OECD` `TV` `DNA` `CO` `PPT`, 그리고 「대기시간 **II**」의 `II`.)

실제로 풀이가 필요한 것: `POE`(5·10강) · `TWA`·`FAR`(11강) · `CER`·`SSI`(12강) ·
`SSI`·`STS`(13강) · `UDL`(14강) · `PCK`(18강).

### D5 앞으로 배울 강

**규칙** 학생이 읽는 글에서 **뒤 차시를 번호로 부르지 않는다.**
「12강에서 배우는 CER」이 아니라 **「나중에 배우는 CER」**.

- **앞 차시는 불러도 된다.** 18강이 「1강에서 여러분이 적은 답」을 꺼내는 것은 그 수업의 내용이다.
- **강사 대본(`instructorScript`)은 면제.** 학생이 보지 않는다.

**왜** 진도가 밀리거나 순서를 바꾸면 그 문장이 거짓말이 된다. 학생은 그 번호를 확인할 길이 없다.

## E · 칸과 말

### E1 칸의 보기

**규칙** `quadrant` 의 칸마다 `hint`, `allocation`·`rank` 의 항목마다 `note` 를 준다.
정답이 아니라 **어떤 종류의 문장을 적는지**만 보여 준다. 한 줄.

```ts
{ id: 'phenomenon', label: '현상', hint: '학생이 눈으로 본 장면. 예: “촛불에 유리컵을 덮자 불이 꺼졌다”' }
{ id: 'evidence', label: '학습의 증거', note: '무엇을 알게 됐는지 확인되는 산출물' }
```

**왜** 「현상」 「목표」 같은 이름만 놓아 두면 처음 보는 사람은 무엇을 적을지 모른다.

### E2 묵은 말

**규칙** 학생이 읽는 글에 아래 말이 남아 있으면 지운다. **기능이 이미 없어졌는데 글만 남은 자리다.**

| 남은 말 | 왜 없앴나 | 어떻게 고치나 |
|---|---|---|
| 확신도 | 1~5 눈금이 이유 칸 위에 아무것도 얹지 못했다 | 그 문장을 이유·근거의 말로 다시 쓴다 |
| 인쇄 활동지 | 실제 수업에서 아무도 펴 보지 않았다 | 통째로 지운다 |
| 퇴실표 | 18주를 함께 가는 강의에 매주 퇴실할 일이 없다 | 「이번 수업 정리」 |
| 봉인된 증거 봉투 | 하는 일과 이름이 달랐다 | 「발표자 선정 봉투」 |

지금 남아 있는 자리: **3강**(「진단」 카드) · **12강**(「반박」 카드) · **15강**(응답 유형 분류).
세 곳 다 「확신도를 함께 수집한다」는 식으로 쓰여 있다. 앱이 더 이상 받지 않으므로 **거짓말이 된 문장**이다.

## 손대지 않는 것 — 이미 전 강의에 걸려 있다

차시별로 다시 할 일이 아니다. 공용 부품 한 곳이 1~18강을 다 그린다.

| 무엇 | 어디 |
|---|---|
| 형성평가 4단계 (제출·공유 → 서로 의견 → 다시 고르기 → 발표자 봉투) | `_common.ts` `buildStandardSteps` |
| 2차 응답이 내 글 **아래에 이어 붙는 것** | `ResponseCollector.tsx` |
| 확신도 슬라이더 제거 · 인쇄 활동지 제거 | 컴포넌트에서 이미 사라짐 |
| 의견 광장 — 한 사람 한 장, 다시 올리면 덮어쓰기 | `repo-firestore.ts` `upsertPost` |
| 의견 광장 필터 2종 (최신순 · 아직 반응 없는 글) | `WallPanel` |
| 배분 칸이 0 에서 멈추고 「점수가 남지 않았습니다」 | `AllocationField` |
| 발표자 뽑기가 형성평가 아래에 · 한 사람 한 자리 | `_common.ts` + `claimLadderSeat` |
