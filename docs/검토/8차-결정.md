# 8차 전면 개편 — 결정 기록

지시서 `docs/8차_변경지시서_전면개편.md` 를 실행하며 **강의자가 답한 것**과 **판단이 갈려 스스로 정한 것**을 여기에 적는다.
강의자가 고치면 그때 고친다. 차시별 내용은 `docs/검토/<과목>-<nn>.md` 에 따로 있다.

## 14절 — 강의자의 답 (2026-09-17)

| # | 물음 | 답 |
|---|---|---|
| 1 | 50분 판·1시간 판(tier) | **없앤다.** 판 미리보기·배지·「수업 후 이어서」·`verify:tiers` 전부 제거. 클래스의 `sessionLength` 는 필드만 남긴다 |

## 이렇게 정했다 — 작업 A (걷어내기)

- **A 단계에서는 옛 차시 파일(1~18강)의 타입을 바꾸지 않는다.** 화면과 검증기에서 기능만 뺀다.
  이유: A 를 먼저 배포해 5·6강을 옛 내용 그대로, 재응답·반응 없이 진행하게 하려면 옛 파일이 그대로 컴파일돼야 한다.
  `studentVoice`·`guide`·`timeline`·`instructorScript`·`tier` 같은 필드는 B-1 에서 새 `Lesson` 타입과 함께 지운다. 화면에는 A 부터 그리지 않는다.
- **제출한 답은 그 자리에서 잠긴다.** 「고쳐 쓰기」·「v2로 제출」·「무엇을 왜 바꿨는가」가 없다. 이미 쌓인 버전은 그대로 두고 마지막 버전을 읽기 전용으로 보인다.
  이유: 원칙 2 「한 번 쓴 것은 다시 쓰지 않는다」. 지시서 A.1 의 「화면에는 v1 만 그린다」는 2차 응답이 없어진 새 차시에서 v1 = 마지막이므로 같은 뜻이다. 옛 차시에서 이미 v2 를 낸 학생에게 v1 을 보이면 자기가 마지막에 낸 답과 다른 것이 보이므로 마지막 버전을 택했다.
- **의견 광장은 카드 목록 하나, 최신순.** 반응·댓글·고정·숨김·정렬·유형 묶기·「이어서 쓰기」·「고치기」·「삭제」를 전부 뺐다. 올리기는 한 번뿐이다.
  저장 계층에서 `toggleReaction`·`addComment`·`pinPost`·`hidePost`·`deletePost` 를 지웠다. 이미 저장된 글의 `reactions`·`comments` 필드는 그대로 남지만 그리지 않는다. 보안 규칙도 글쓴이의 `versions`·`latestV` 만 열어 둔다.
- **강사가 학생 화면에 보내던 것(설명 추가·짝 토론·재응답 요청·미제출 알림)은 전부 뺐다.** 세션의 `notice`·`nudges` 필드와 학생 화면의 안내 카드가 사라진다. 「강사가 이 단계로 이동했습니다」 배너는 C 에서 학생 경로를 학생 전용으로 만들 때 함께 정리한다.
- **AI 유형 묶기(`AiClusterPanel`)는 A 에서는 서술형 응답 목록에만 남긴다.** 의견 광장의 것은 뺐다. C 에서 수업 화면 단추를 여섯으로 줄일 때 「AI 검토」 화면(강의자가 남기기로 한 것) 안으로 옮긴다 — `verify:modules` 가 「분류를 호출하는 곳이 하나는 있어야 한다」를 요구하므로 아예 지우지는 않는다.
- **A.2 의 글 규칙은 `verify:wording` 에 넣되 새 골격(`layout` 이 있는 차시)에만 실패로 걸린다.** 옛 차시는 개수만 알린다.
  이유: 옛 18차시는 F·G 에서 통째로 다시 쓰므로 지금 고칠 대상이 아니다. 예전 검증기들이 「아직 안 고친 차시는 세기만 한다」고 한 방식과 같다.
- `verify:lessons` 는 A 에서 여섯 층·강사 대본·타임라인 합계 규칙을 빼고 남겨 두었다가 B 에서 `verify:concepts` 로 바꾼다. `audit:lesson` 은 D1~D3·G1~G3 을 빼고 남겨 두었다가 B 에서 지운다.
- 옛 차시의 응답 경로(`step-recall`·`step-auction` …)는 그대로 둔다. 새 골격의 단계 id(`intro`·`concepts`·`activity`·`wrapup`)와 겹치지 않으므로 옛 응답은 지워지지 않고, 1·2강은 `legacyStepIds` 로 포트폴리오에서 계속 보인다 (B-1).

## 이렇게 정했다 — 작업 B~E (골격 · 수업 화면 · 게임 · 1강 본보기)

- **단계 id 는 고정이다** — `intro · concepts · activity · (concepts-2 · activity-2) · wrapup`. `buildSteps(lesson)` 이 layout 에서 만든다. 옛 골격의 응답 경로(`step-recall …`)는 색인의 `legacyStepIds` 로만 남아 포트폴리오·제출 현황·삭제가 그 경로를 안다. 이유: 내용 파일을 불러오지 않고도 응답 경로를 알아야 한다(부록 ①).
- **학생의 쓰는 칸은 강사가 「단계 열기」를 누른 뒤에만 열린다** (`session.openSteps`). 자료와 개념 카드는 늘 보인다. 이유: 7.1 「단계 열기는 그 단계의 모든 칸을 연다」. 강사 없이 혼자 보는 학생은 읽기만 한다.
- **의견 광장·모둠·게임은 제출한 뒤에만 보인다.** 이유: 원칙 2·3. 모둠 게임이 모둠 단계 뒤에 온다는 6.1 도 이것으로 지켜진다.
- **게임 상태는 (서버 시드 · 참가 · 입력 · 서버 시각)의 함수다** (`src/lib/game-core.ts`). 강사 화면이 「끝났다」를 보면 세션에 결과를 적고 발표 횟수를 올린다. 강사 화면이 게임 진행자 루프를 돌지 않는다. 이유: 모든 화면이 같은 것을 계산하면 서버가 결과를 내려보낼 필요가 없고, 강사 화면이 잠깐 끊겨도 학생 화면이 멈추지 않는다.
- **추정 게임의 답 분포는 강사가 시작할 때 게임 상태에 넣는다.** 이유: 학생은 규칙상 `groupInputs` 전체를 읽지 못한다.
- **참가자가 없으면 「게임 시작」이 발표 횟수 가중 추첨이다.** 재추첨은 「게임 시작」을 다시 누르는 것(새 판), 수동 지정은 결과 옆의 선택 상자다. 이유: 7.3 의 단추 여섯을 지키면서 6.1 의 가중치·재추첨·수동·비상을 유지한다.
- **1강 사다리·2강 봉투는 옛 엔진(ladder.ts) 그대로.** 봉투는 같은 씨앗의 대응을 봉투 그림으로 보인다. 강사 단추는 「게임 시작」 하나 — 첫 누름이 자리를 열고 두 번째가 결과를 연다. 이유: 6.3 「유지」와 7.3 단추 여섯.
- **「응답 펼치기」는 단추가 아니라 접기 요소다** — 「응답 n/N ▸」 「올라온 글 n ▸」 「모둠별 ▸」. `verify:teach` 는 이것을 `<summary>` 로 센다. 학생만 누르는 [참가]와 명단 서랍은 여섯 밖의 예외로 두었다. 단계 알약(`role="tab"`)은 이동이지 조작이 아니다.
- **루미 런의 코스·제한 시간은 학생 티켓에도 준다. 등수만 강사에게.** 이유: 학생 화면도 같은 코스를 그려야 한다. 비밀은 등수다(부록 ②).
- **교육론 1강은 교수법 1강 파일을 그대로 다시 내보낸다** (`edu/lesson01.ts`). 검토 문서·카드 id·이론 항목을 함께 쓴다. `audit:draft`·`verify:concepts`·`verify:theory`·`verify:games` 가 1강 짝을 예외로 둔다. 이유: 강의자 답 4.
- **`verify:standards` 를 없앴다.** 이유: `curriculumLink` 가 새 `Lesson` 타입에 없다. 성취기준은 교육과정 찾기 화면(남김)에서 다룬다.
- **`verify:modules` 는 AI 검토 관문만 본다.** 전용 화면 모듈(dataStudio · nodeCanvas …)은 8차 골격에서 없앴다. 응답 유형 묶기는 검토대 안에서 단계를 골라 요청한다.
- **교재 문장 단위 대조는 차시 사이 중복으로 대신한다.** 이유: 교재 원문이 저장소에 없다. OCR 오독·반복 템플릿 검사가 교재 유입을 막고, `verify:content` 가 두 차시에 같은 문장이 있으면 실패한다.
- **1강 검토 문서**: 도입은 선택 하나 · 옛 3단계(두 수업 비교)는 뺐고 수업 B 는 카드 2 의 장면으로 · 활동은 배분(경매) 유지 · 정리 문항은 「어디에 점수를 달리 주었겠는가」. 자세한 것은 `docs/검토/method-01.md` 의 「이렇게 정했다」.
- **강사 화면의 시간(「5분」)은 강사 화면에만 있다.** 학생 화면에는 없다(3차 D). `verify:wording` 은 그 자리에 `wording-ok` 를 둔다.

## 이렇게 정했다 — 작업 F·G (차시 내용)

- **게임 배치는 6.3 초안에서 반응 속도 게임을 학기당 2회로 줄였다.** 초안은 동시에(6·16강)·늦게(13)·순간 포착(17)으로 반응 속도 게임이 넷이라 6.1 「한 학기에 두 번 이하」와 어긋난다. 「동시에 눌러라」를 빼고 6강 비밀 합 · 9강 릴레이 · 12강 비밀 합 · 16강 릴레이로 두었다. 교육론도 11강 동시에 → 추정. 최종 표는 `docs/검토/_작성-지침.md`. 두 과목이 같은 주에 같은 게임을 쓰지 않도록(8.3) 교육론 배치를 그 표에서 어긋나게 짰다.
- **모둠 데이터 형식**은 과목마다 연속 차시에 같지 않게, 배분은 교수법 3회(1·15·18) · 교육론 2회(5·12)로 정해 표에 적었다. 작성자는 표를 따랐다.
- **교육론 2~12강의 옛 응답 경로**는 `EDU_LEGACY_STEP_IDS`(`step-open · step-concepts · step-module · step-formative · step-wrapup`)로 두었다. 이유: 교육론 클래스도 8차 이전에는 옛 18차시 내용을 썼으므로 그 응답이 포트폴리오에서 계속 보여야 한다.
- **공개 차시의 이론 배경**: 교수법 2~6강은 옛 카드 id 를 살려 t02~t06 의 링크를 유지하고 `plainTerms`·`bridgeToPlain` 만 새 본문에 맞췄다. 7강(t07)·교육론 2강(te02)은 새로 썼고 전부 `verified: false` 다 — 원문 대조 전이라 인용은 넣지 않았다. 80분 차시는 카드가 여섯이라 이론 항목도 여섯이다.
- **미공개 차시(교수법 8~18 · 교육론 3~12)는 이론 배경 없이 두었다.** `verify:theory` 는 공개 차시에만 이론을 요구한다. 공개할 때 쓴다.
- **검토 문서의 줄머리**: 자료 본문은 들여쓰고 첫 칸에서 시작하는 「과제」 줄만 과제문으로 읽는다(`audit:draft`). 4강 상황 첫 줄이 「과제  …」로 시작해 과제문으로 잡혔던 것을 이렇게 풀었다.
- **검증기 오검출 두 가지를 고쳤다.** 「좀처럼」과 한 줄짜리 선택지·카드는 비유 검사에서 뺐다(뒤에 풀어 줄 문장이 올 자리가 없다). 루미 런은 3·4강에 연속으로 있는 것이 강의자의 답이므로 연속 배치 검사의 예외다.
- **배포는 교수법 1~7강과 교육론 1~2강(공개 차시)이 새 골격으로 다 들어온 뒤에 한다.** E 만 배포하면 지금 진행 중인 학기의 2~18강이 사라진다. 12절의 순서(E 배포)에서 이 점만 벗어났다.
- **로컬 개발 서버(vite)에는 서버 함수가 없어** `/api/game/time` · `/api/picker/draw` 가 404 다. 그때 화면은 시각 오프셋 0 · 로컬 시드로 돈다(설계된 대체). 배포에서는 Pages Functions 가 답한다.

## 강의자 추가 지시 (2026-09-18) — 발표 모드 · 고정 규칙 · 단계 시간 · 잠깐 확인

강의자가 수업 화면을 보고 네 가지를 지시했다. 판단이 갈린 곳만 적는다.

- **발표 모드를 뺐다.** 글자 키우기(`--present-scale`)와 단추가 함께 없어졌다. 실명을 닉네임으로 바꾸는 일은 「실명 가리기」 체크 상자 하나가 맡는다. 이유: 이름 가리기는 프로젝터에 실명이 나가지 않게 하는 안전장치라 남겨야 하는데, 발표 모드가 없으면 그것을 켤 자리가 하나만 남는다. 수업 중 단추는 다섯이다 (`TEACH_BUTTONS`).
- **모둠 나누기의 고정 규칙(반드시 같이 · 반드시 따로)을 화면과 호출에서 뺐다.** 배정 엔진(`shared/groups-core.ts`)의 `mustTogether` · `mustApart` 는 선택 필드라 그대로 두었다. 이유: 엔진·서버·`verify:groups` 가 같은 코드를 쓰므로 거기를 고치면 검증된 계산이 흔들린다. 화면이 보내지 않으면 서버가 빈 목록으로 돈다.
- **단계 시간을 모두 뺐다.** `Step.minutes` 필드, 수업 화면의 「n분」 배지, 차시 목록의 골격 열(80분/40분/50분), 검토 문서 절 제목의 「(15)」, README 의 표. 이유: 강의자 말대로 수업이 어떻게 흘러갈지는 그 자리에서 정해진다. 차시 길이(`edu80` · `edu40`)는 개념·활동이 한 벌인지 두 벌인지를 가르는 골격 이름이라 코드에 남겼다. 화면에는 나오지 않는다. `verify:teach` 가 코드에 `minutes}분` · `발표 모드` 가 다시 들어오는 것을 막는다.
- **개념 카드마다 「잠깐 확인」 4지선다를 되살렸다 — 이유 칸 없이.** 한 번 고르면 잠기고, 맞았는지와 정답 자리를 바로 보여 준다. 정해진 것:
  - **저장**: 개념 단계(`concepts` · `concepts-2`)의 응답 문서 하나에 `{카드 id: 보기 자리}` 로 모은다. 옛 개념 확인(`{choice, reason}`)과 같은 자리라 새 보안 규칙이 필요 없다. 새 판이 앞 판을 대신하므로 화면이 저장을 줄 세워 앞 답을 담아 낸다.
  - **쓰는 칸으로 세지 않는다.** 원칙 1(차시마다 쓰는 칸 셋, 80분은 넷)은 그대로다. 제출 현황·포트폴리오는 개념 단계를 뺀다 — 포트폴리오는 내용 파일 없이 그리므로 보기 자리만으로는 읽을 수 없다. 분석 화면은 개념 단계의 응답 수를 그대로 보인다(몇 명이 풀었는지는 쓸모가 있다).
  - **「단계 열기」와 상관없이 풀 수 있다.** 쓰는 칸이 아니고, 개념 단계에 단추를 하나 더 두지 않으려는 것이다.
  - **강사 화면**은 물음과 보기를 펼쳐 두고 정답·분포를 「응답 n/N ▸」 접기 안에 둔다. 띄운 화면에 정답이 먼저 보이지 않게 하려는 것이다.
  - **문항의 꼴**(`verify:concepts`): 물음은 장면을 주고 「가장 ~한 것은?」으로 묻는다 — 정의를 되묻지 않고 부정으로 묻지 않는다. 보기 넷은 길이가 비슷하다 — 최대/최소 2배 이하, 정답이 오답 평균의 1.25배 이하, 과목 전체에서 정답이 가장 긴 보기인 문항 30% 이하. 정답 자리는 과목마다 자리별 15~35%이고 차시 안에서 모두 같지 않다. 물음·보기가 카드 문장을 16자 넘게 옮기지 않고, 카드 이름이 정답에만 들어가지 않는다. 강의자가 짚은 두 가지(너무 쉬움 · 긴 보기가 답)를 검사기가 셀 수 있는 만큼 센 것이다.
  - **정답 자리는 미리 정해 작성자에게 주었다.** 과목 전체 균형은 여럿이 나눠 쓰면 맞추기 어렵다. 차시 안에서 네 자리가 다 한 번씩 나오게 하지도 않았다 — 셋을 풀면 넷째를 짐작할 수 있다.
  - **문서가 먼저다.** 검토 문서의 카드 끝에 「확인」 블록(물음 · ①~④ · 정답)을 쓰고 `npm run sync:checks` 가 코드로 옮긴다. `audit:draft` 가 양쪽을 대조한다.
  - **두 과목의 문항이 같은 장면을 쓰지 않게 했다.** 네 작성자가 동시에 쓰느라 두 과목에 함께 있는 개념(학습 이론 · 모형 · 형성평가 · 쟁점 등)에서 장면이 겹쳤다 — 태풍 자료로 행사 미루기, 지진 분포도로 판의 경계, 설탕 용해, 용수철 그래프, 자석과 알루미늄 캔, 전류 소모, 쇠와 나무의 온도. 문장이 달라 `verify:course` 는 통과했지만 8.3 의 뜻(두 과목은 자료·상황을 나누지 않는다)에 어긋난다. 다른 과목의 카드 「교실에서」 장면을 문항이 쓰는 것(진공 종, 양파 표피 현미경, 물컵 속 젓가락, 컵 속 얼음 녹이기, 퇴적층 순서, 공기의 무게)도 겹침으로 보았다. 교수법 쪽 열넷, 교육론 쪽 일곱 문항의 장면을 바꾸었다. 같은 개념이라 정답의 생각(예: 보편적 학습 설계는 모두를 위한 선택지)이 닮은 것은 남겼다 — 개념이 같으면 맞는 판단도 같다.
  - **결과(잠깐 확인)** — 교수법 72문항 · 교육론 49문항(1강은 같은 네 문항). 정답 자리는 교수법 18/18/18/18 · 교육론 12/12/13/12. 정답이 넷 가운데 가장 긴 보기인 문항은 두 과목 모두 8%(교수법 6 · 교육론 4)이고, 보기 길이 차이는 대개 한두 글자라 길이로는 답이 보이지 않는다.


## 강의자 추가 지시 (2026-09-21) — 교육론 2강의 발표자 뽑기를 교실 구슬 레이스로

강의자가 따로 배포된 활동 앱(교실 구슬 레이스)을 교육론 2강의 두 활동에 붙이라고 지시했다. 활동 3(활동 1)은 회전 관문 · 가장 먼저 도착한 2명, 활동 5(활동 2)는 포털 연구소 · 가장 늦게 도착한 2명이다. 판단이 갈린 곳만 적는다.

- **붙이는 안내서와 배포된 활동 앱이 달랐다. 앱을 따랐다.** 안내서는 맵 id 를 `ext-portal`·`ext-wind`·`ext-magnet` 으로, 규칙을 `{kind:'firstN'}`·`{kind:'lastN'}` 으로 적었다. 배포된 앱에는 그런 id 도 규칙도 없다 — 포털 연구소는 `mix-portal` 이고 규칙은 `topK`(상위 k명)·`bottomK`(하위 k명)다. 활동 앱은 고칠 수 없으므로 우리 쪽을 앱에 맞췄고, 맵 목록과 규칙 표를 `src/lib/marble.ts` 한 곳에 두어 차시 파일과 `verify:games` 가 같은 값을 쓴다. 활동 앱의 화면에서 두 규칙을 직접 돌려 확인했다 — 8명 기준 회전 관문 + 상위 2명은 16초, 포털 연구소 + 하위 2명은 28초에 끝났고 당첨자 수와 이유 문장이 맞았다.
- **서버를 하나도 만들지 않았다.** 루미 런은 티켓·서명·webhook 이 있지만 이 게임은 `mode: 'local'` 로 강사 브라우저에서만 돈다. 학생 기기는 참가하지 않고 학생 화면에는 결과만 뜬다. `verify:games` 가 구슬 레이스 파일에 `apiPost`·`fetch(`·`/api/` 가 들어오는 것을 막는다.
- **명단은 수강생 전원이다.** 다른 게임처럼 [참가]를 누른 사람만 달리게 하지 않았다. 한 화면에서 도는 게임이라 참가 단추를 누를 기기가 없고, 강의자의 지시(아이디를 받아서)도 명단을 넣으라는 뜻이다. 당첨자의 `participantId` 가 우리 uid 라 학생과 바로 맞는다 — 모르는 id 는 버린다.
- **결과는 기존 구조에 적는다.** 새 구조를 만들지 않고 `finalizeGame` 하나로 세션의 게임 상태 · 뽑기 기록(`picks`) · 발표 횟수(`presentCount`)에 적는다. 라이브러리 게임의 확정 코드도 같은 함수로 모았다. 씨앗 자리에는 활동 앱이 준 라운드 id 를 적는다.
- **확인해 줄 서버가 없다는 것을 화면에 적는다.** 활동 앱이 `serverVerified: false` 를 준다. 결과 배지에 「화면에서 계산한 결과」, 무대 아래에 「성적이나 평가에는 쓰지 않습니다」를 둔다.
- **다시 뽑기는 같은 단추다.** 수업 중 단추를 늘리지 않으려고 「게임 시작」 하나가 새 판까지 맡는다(`resetRound` → 새 판). 끝난 판에서 누르면 두 번째 판이 시작된다.
- **localhost 에서는 확인할 수 없다.** 활동 앱이 `frame-ancestors 'self' https://nc1395.labbitory.com https://scienced.labbitory.com` 을 보내므로 개발 주소에서는 iframe 이 아예 막힌다. 검은 칸으로 멈추지 않게 8초 안에 `ready` 가 오지 않으면 그 이유를 화면에 적는다. 그래서 로컬에서는 화면·저장·결과 카드까지 확인하고, 활동 앱 자체는 그 앱의 주소에서, 붙인 모습은 배포 주소에서 확인했다.

## 강의자 추가 지시 (2026-09-21) — 강사 화면의 첫 화면을 수업으로

강의자가 「강사 메뉴에 들어가면 뭘 먼저 눌러야 할지 모르겠다」고 했다. 수업을 열려면 클래스 카드 → 차시 목록 → 수업 열기로 세 번을 눌러야 했고, 카드에는 차시 목록 · 수강생 명단 · 모둠 관리 · 수강 등록 마감 · 지우기 · 보관이 **같은 크기로** 놓여 있었다. 지시서 7.4 의 「클래스 목록 → 차시 목록 → 수업 화면」을 글자 그대로 옮긴 결과다. 이렇게 고쳤다.

- **강사 홈은 지금 클래스의 차시 목록 하나다.** 상단바의 클래스 고르개가 이미 클래스를 바꾸므로 홈에서 클래스를 다시 고르게 하지 않는다. 다른 클래스는 아래에 이름만 두어 누르면 전환한다.
- **맨 위에 「이어서 할 차시」 하나를 크게 둔다.** 마지막으로 연 차시(이 브라우저에 남는 값, `src/lib/last-taught.ts`)를 쓰고, 없으면 공개된 차시 가운데 마지막을 쓴다. 저장하지 못해도 화면은 그대로 돈다 — 그래서 실패를 삼켜도 되는 유일한 자리다.
- **수업이 아닌 일은 「클래스 관리」 탭 셋으로 모았다** — 수강생 명단 · 모둠 · 클래스 설정(등록 · 보관 · 지우기 · 새 클래스). 홈에는 매주 쓰는 것만 남긴다. 기존 주소(`…/students` · `…/groups`)는 그대로 열리고 탭 머리만 붙었다.
- **새 클래스 만들기는 설정으로 내렸다.** 학기에 한 번 쓰는 일이라 홈의 첫 단추가 될 이유가 없다. 클래스가 하나도 없을 때만 홈에서 바로 만든다.
- **지우기·보관은 단추를 작게 두고 무엇이 사라지는지 화면에 적는다.** 예전에는 카드에서 곧바로 눌리는 자리에 있었다.
- 학생 계정 · 학습 분석 · AI 검토는 과목 전체를 보는 도구라 홈 머리의 글자 링크로 둔다 — 수업 열기와 같은 크기로 두지 않는다.
